# 설계 결정

왜 그렇게 정했는지를 남기는 문서. 구현 방향이 애매할 때 참조한다.

## 1. Next.js를 쓴다

카카오톡 링크 공유가 주 유입 경로라 캡슐마다 다른 OG 태그가 필요하기 때문에 Next로 결정했다.

## 2. 백엔드는 Supabase, 열람 차단은 RLS

"만료 전에는 아무도 못 본다"가 이 서비스의 기반이다.
프론트에서 숨기면 네트워크 응답에 원문이 그대로 보이는 문제가 있어 RLS 정책에 조건을 걸어 DB가 직접 막는다.

## 3. 시각은 주입받는다

상태가 시간에 따라 바뀌는데 몇 달을 기다려 테스트할 수는 없기 때문에 시각을 주입받아 테스트하고자 한다.

`getCapsuleStatus(period, now)`가 유일한 판정 지점이고 시각을 인자로 받는다.

## 4. 로그인 없음

"링크 하나로 여러 명이 참여"가 핵심 흐름이라 비로그인으로 모두가 쉽고 빠르게 접근해 편지를 작성할 수 있도록 한다.
편지 수정은 작성 시 정한 닉네임과 비밀번호로 검증하며, 닉네임 또는 비밀번호 분실 시 복구 불가임을 UI에 명시한다.

비밀번호 해싱과 검증은 Postgres 함수(pgcrypto)에서 처리한다.
클라이언트는 rpc 호출만 하고, 해시값은 클라이언트로 내려보내지 않는다.

## 5. 만료일 알림은 .ics로

만료일 알림을 이메일 발송으로 처리하기 위해서는 도메인 인증이 필요한데, 도메인은 사지 않기로 결정했다.

따라서 만료일 알람은 캘린더 파일 다운로드로 제공하고자 한다.
버튼을 클릭하면 원하는 사용자 모두가 만료일을 캘린더에 담아갈 수 있도록 한다.

## 6. 날짜 기준

`timestamptz`로 UTC 저장, 표시는 KST로 한다.
날짜를 선택하면 해당 날짜 KST 00:00으로 해석한다. 시간은 별도로 선택할 수 없도록 한다.

`입력 마감일 < 만료일`, 둘 다 캡슐 생성일 이후로만 설정 가능, `만료일` 상한은 10년으로 한다.

## 7. 해시 컬럼은 컬럼 단위 GRANT로 가린다

RLS는 행 단위라 특정 컬럼만 숨길 수 없다.
해시 컬럼을 제외한 컬럼 목록을 명시해 grant한다. 테이블에 컬럼을 추가할 때 grant 목록도 함께 갱신해야 한다.

## 8. slug는 DB DEFAULT 함수로 생성한다

클라이언트가 slug를 지정할 수 있으면 기존 캡슐의 slug를 선점하거나 추측할 여지가 생긴다.
grant에서 slug의 insert 권한도 제외한다.

## 9. 캡슐 안에서 닉네임은 유일하다

편지 수정을 닉네임 + 비밀번호로 하기 때문에, 같은 캡슐에 동명이인이 있으면 어느 편지를 수정할지 특정할 수 없다.
작성 시 중복 닉네임 안내가 필요하다.
